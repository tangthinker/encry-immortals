# 09 · 系统不变量清单（新增章节）

> 不变量是"用一句话说清、可写成断言、可写成测试"的系统性质。母方案描述了机制，但没有把机制背后的"必须永远成立的事实"提炼出来。本清单的每条都会在 12 章对应至少一个测试；实现中若某处代码无法保证某条不变量，应当视为设计缺陷而非实现细节。

## 9.1 存储层不变量

| ID | 不变量 | 强制点 | 违反后果 |
|---|---|---|---|
| **I1** | `data/` 下的文件一经出现，其内容字节**永不改变** | 写入路径只有 `rename` 进入，代码中不存在对 `data/` 的 `O_RDWR` 打开 | 云端同步冲突、历史快照失真 |
| **I2** | 每个 pack 只被**一个** `txn_id` 引用（下一条 journal 不会追加到旧 pack） | pack 的 `pack_id` 在创建时生成并写入 AAD；rollover 后不再打开旧 pack | 不可变性与"pack 可独立校验"同时失效 |
| **I3** | 任意 `slice_entry` 的 AAD 必须包含其真实 `pack_id / offset / index / txn_id / codec` | 03 章 AAD 拼装函数是唯一出口，且 `slice_offset` 由 writer 计算、由 reader 的 seek 位置复验 | 切片可被搬运/重排 |
| **I4** | 从任意点开始的"checkpoint + 增量重放"结果，与 genesis 全量重放结果**逐字节相同** | 04 章 4.4 | 快照穿梭给出错误的历史视图 |
| **I5** | 每个 journal 的 `prev_hash` == SHA-256(前一个 journal 的完整字节)（seq=1 时为 genesis 常量） | 04 章 4.3；写入时前一个文件已 fsync | 链断裂检测失效 |
| **I6** | journal 文件内记录的 `seq` 与其文件名解析出的序号严格一致 | 04 章 4.1（seq 在 AAD 中） | 重编号攻击 |
| **I7** | 每个切片的 AEAD 解密成功，且解密后长度 == `plain_len`，且 SHA-256 == `slice.plain_sha256` | 03 章解析器 + 05 章 restore | 静默数据损坏 |
| **I8** | 无变更时**不产生** journal | 05 章扫描阶段 | 序号被空提交灌水，锚点失去意义 |
| **I9** | `packs[]` 中出现的每个 pack 都在 `data/` 中存在，且 size/sha256 与文件实际一致 | S4 阶段在 pack 已 fsync + rename 之后才计算 sha256 | journal 引用不存在的包 |
| **I10** | `meta/` 中的 journal 序号连续（1..N 无空洞），且最后一个可解密 | restore 前的链扫描 | 中途缺失被当成正常尾部 |

## 9.2 平面边界不变量

| ID | 不变量 | 强制点 |
|---|---|---|
| **I11** | `~/.config/apex-vault/` 内**不含**任何来自数据平面的内容（无明文文件内容、无 pack/journal 明文副本） | 代码中控制平面与数据平面无共享写入路径；`doctor` 定期检查 |
| **I12** | `TargetDir` 内**不含**任何密钥材料、明文、或可读的元数据（只剩 `.tmp/` `.apex.lock` `data/` `meta/` 四类） | 01 章 1.1 的条目白名单 |
| **I13** | `state.db` 中**不含**明文路径（只有 `HMAC(PathKey, path)`） | D-13 |

## 9.3 状态与并发不变量

| ID | 不变量 | 强制点 |
|---|---|---|
| **I14** | `state.db` 可以被完全删除并从 journal 全量重建，重建结果与原库在语义上等价 | `apex rebuild-state`；I1–I10 成立则此条成立 |
| **I15** | 同一时刻对同一 `TargetDir` 只有一个写者 | 01 章 1.4 三层防御 |
| **I16** | 源文件在"读取开始"与"读取结束"之间未发生变化，否则该文件不得进入 pack | 05 章 5.4 前后 stat 比对 |
| **I17** | 任何一次提交完成后，`data/` 中的 pack 数 ≥ `meta/` 引用的 pack 数（可以有孤儿，不能有缺失） | 05 章 S3 → S6 顺序 |

## 9.4 密码学不变量

| ID | 不变量 | 强制点 |
|---|---|---|
| **I18** | 每个 AEAD 加密使用全新的 24 B 随机 nonce，**绝不复用**（跨进程、跨机器、跨恢复） | 02 章 2.6；代码中 nonce 只能来自 CSPRNG，禁止任何计数器/派生拼接 |
| **I19** | KDF 参数在 init 后**永久冻结**：import/restore 时只读，绝不用本机校准结果覆盖，也不存在参数升级路径 | 02 章 2.7 / 2.8 |
| **I20** | 密码错误与文件损坏返回**同一条**错误与同一个退出码 | 02 章 2.9 |
| **I21** | `vault_id` 不一致的 journal/pack 必须解密失败（而不是"能解但内容可疑"） | AAD 中绑 vault_id（02 章 2.5） |

## 9.5 不变量 → 测试映射

| 不变量 | 测试类型 | 用例要点 |
|---|---|---|
| I1 | 代码审计 + 静态检查 | 断言 `data/` 下无 `os.OpenFile(..., os.O_WRONLY...)` 调用 |
| I2 | 单元 | 同一文件两次修改 → 必然产生两个 pack |
| I3 | 属性测试 | 随机篡改 AAD 任一段 → 解密必失败 |
| I4 | 属性测试 | 随机文件树 + 随机 checkpoint 间隔 → 两条路径的树 100% 相同 |
| I5/I6 | 属性测试 | 改一个字节 / 改文件名 → 必报错且退出码正确 |
| I7 | 故障注入 | 篡改密文、截断 footer、改 `plain_len` → 必须明确报 `E12` |
| I8 | 单元 | 无变更 → 退出码 0 且 `meta/` 无新增 |
| I9 | 集成 + 故障注入 | 在 S3 与 S4 之间 kill → 孤儿包不被引用 |
| I10 | 集成 | 删除中间 journal → `E11 CHAIN_BROKEN` |
| I11/I12/I13 | 静态检查 | 检查 Target 目录白名单；`sqlite3 .dump` 中无明文路径 |
| I14 | 集成 | 删 state.db → rebuild → 后续 `fast` 扫描得到相同差异集 |
| I15 | 集成 | 两个进程并发 backup → 第二个收到 `E20` |
| I16 | 故障注入 | 读大文件时后台改写 → 文件被标 STALE，不进入 pack |
| I17 | 集成 | 任意 kill 点后统计 `data/` 与 journal 引用数 |
| I18 | 代码审计 + 单元 | nonce 生成函数是唯一入口；跑 10^7 次断言无重复 |
| I20 | 单元 | 密码错 / `vault.meta` 损坏 → 输出与退出码完全一致 |
| I21 | 集成 | 用 B 库的 `vault.meta` 解 A 库的 journal → 必须失败 |

## 9.6 边界情形清单（每条都必须有明确行为，不允许"未定义"）

| 情形 | 行为 |
|---|---|
| 空文件（0 字节） | `slices=[]`，restore 创建空文件（03 章 3.5） |
| 空目录 | 写入 `dirs[]`，restore 创建 |
| 只有空目录的源 | 产生一个 journal（有 `dirs` 变更） |
| 源目录为空且不存在任何文件 | 产生一个 journal（记录源根目录的 mode）或直接报错？**结论**：产生 journal |
| 文件名含换行/制表符 | 允许，原样存储（path 是 bytes 级字符串） |
| 文件名含非法 UTF-8 | **拒绝**并 `E12`（跨平台不一致） |
| 单个文件名长度 > 255 B | **拒绝**并 `E12`（多数文件系统的硬限制） |
| 路径总长超限 | Windows 上 fail-fast；类 Unix 上允许（直到 `PATH_MAX`） |
| 文件在备份过程中被删除 | 视为 `DELETE`（若判定为稳定删除）或 `STALE` 跳过 |
| 文件在备份过程中被重命名 | 表现为 `DELETE` + `ADD`（不做 rename 检测，v1） |
| 完全相同的两个文件 | 各存一份（无去重，见 11 章） |
| 硬链接 | fail-fast（01 章 D-18） |
| 权限位含 setuid/setgid | 原样记录，restore 时**默认不还原** setuid 位（安全考虑），`--restore-suid` 可开启 |
| 时区 | 只用 Unix 时间戳与纳秒，不存时区 |
| DST 切换 | 无影响（不使用本地时间表达） |

## 9.7 待确认

1. I1 是否允许"孤儿清理时删除 `data/` 下的文件"？**结论**：允许，但仅限**从未被任何 journal 引用**的文件，且需要显式 `--prune-orphans --yes`。这不违反 I1（I1 约束的是"被引用过的数据"，措辞应为"任何被至少一个 journal 引用的 pack 永不改变内容，且在其最后一次被引用之前永不删除"）。**建议**把 I1 的正式表述改为这句。
2. 是否需要一个 `apex doctor --self-check` 把所有可运行时验证的不变量跑一遍？**结论**：需要，且应作为 CI 的必过项。
